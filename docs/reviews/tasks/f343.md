# F343 — how roomy a list is, and how loud its marks are

Done 2026-11-21. `lib/ui/controls.zm`, `lib/ui/theme/theme.zm`, six tests.

Three things a sidebar wanted and could not have. All three came from the same screen — the
health-record port's menu, held against the web application it copies — and the third only appeared
once the first was fixed.

## A list could not be comfortable

`row_height` was `line_for(body) + style.space.s`. The comment above it argues, rightly, that a
row's height *is* a line of text and so must be measured like one rather than stored as a number;
it then adds `space.s` and stops.

**But `space.s` is also the gap between two chips, and between an icon and its label.** So a menu
that wanted the 40-point rows of the application it copies — `py-2.5`, ten points above and ten
below — had to make every small gap in the window bigger to get them. 26 points against 40, and no
way to close it.

`Style.row_air`, defaulting to `space.s`, so **every look that does not mention it is unchanged**.
`at_density` scales it with the rest of the spacing, or a `Spacious` look would have grown every
gap and kept its lists exactly as tight.

Still added to a measured line rather than replacing one: a theme that enlarges its type still gets
rows that fit.

## A row's mark was as loud as its words

F340 painted the mark in the row's one ink, arguing that an icon left in the list's ink vanishes
into a selected row's accent band. That argument is about the **hue** and still holds — so the fix
keeps the hue and spends some of the alpha. A selected row's mark is still `on_accent`.

What it fixes is the resting row: an icon as heavy as the words beside it reads as a second word.
Every sidebar draws the mark lighter; the application this was measured against uses `#9ca3af`
against `#374151`, which is about this much.

**Alpha rather than a mix toward the background**, because `Parts.face` is a `Paint` and may be a
gradient: there is no single colour to mix toward, and fading works over whatever is behind.

## And then the mark grew with the row

`row_of` stretches its children across the row, and a `Fixed` takes whatever box it is given. So
once a look asked for roomy rows, a 14-point icon was drawn at forty.

**Invisible before this task and inevitable after it.** The mark is centred across the row now; the
test measures the ink at two row heights and insists it is the same, with a second test beside it
confirming the row really did get taller — or the first would pass by measuring nothing.

## Watched fails

| removed | what reddened |
|---|---|
| `row_air` (back to `space.s`) | `a_looks_row_air_decides_how_tall_a_row_is` |
| the quieter mark | `a_rows_mark_is_quieter_than_its_words` |
| the centring | `a_rows_mark_does_not_grow_with_the_row` |

And `a_derived_look_keeps_the_old_row_height` is the one that says this was safe to add: every
theme in the register still gets a line plus `space.s`, exactly as before.

## A fourth, from the same screen collapsing

`controls.mark_slot` — **the column a row's mark sits in, whether or not the row has words beside
it.**

A list of files, or a menu, wants its marks in a column: an icon at each row's leading edge lines
up only while every icon is the same width, and the moment one is not the column wobbles. A slot
fixes that — and it is what makes **collapsing a menu to its marks leave them exactly where they
were**. Without it, a mark-only row centred its icon and a worded row did not, so every icon slid
sideways as the menu closed, which reads as the menu redrawing rather than narrowing.

**Twice the body size**, which is the proportion the application this was measured against uses: a
28-point slot around a 15-point glyph. Derived, so a look that enlarges its type gets a wider
column without saying so — and an application that wants a face at the top of its menu to share
that column can ask for the number rather than matching it by hand, which is how the same
application's avatar came to sit four points right of every icon beneath it.

Watched fail: taking the slot out of `marked_row` moves the mark by 7 points between the menu's two
states.

## What is still not sayable

**What a suggested button looks like independently of a selection** — F342's note, unchanged.

**A row's air is one number, not a padding.** Ten above and ten below is `row_air: 20`; nine above
and eleven below cannot be said. Nothing has wanted that, and a `Insets` here would invite a
caller to make a row whose text is not on its centre line.
