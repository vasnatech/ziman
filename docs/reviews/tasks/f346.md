# F346 — eliding a title cost more than laying out the screen it was on

Done 2026-11-25. `lib/ui/widget.zm`, `tests/stdlib/widget_test.zm`.

Raised by the health-record port, still too slow to use after [F345](f345.md). Its window spent
**12 ms of a 31 ms frame building the widget tree** — before any of it was laid out — and
`widget.elided` was most of that.

## What it was

`elided` answers the longest prefix of a title that fits a column, with an ellipsis. It found it
by taking **one character off the end at a time**, re-measuring the whole prefix each round:

```ziman
var kept = prelude.len(text)
while kept > 0 {
    val cut = prelude.concat(prelude.substring(text, 0, kept), mark)
    if width_in(m, which, cut, size) <= room { return cut }
    kept = kept - 1
}
```

For a title that has to lose half its characters that is tens of measurements of tens of
characters each — and this is called **while the tree is being built, once per label, on every
frame**. A list of ten rows elides ten titles.

Measured on three real titles against a real face:

| room | per elide, walking | per elide, bisecting |
|---|---|---|
| 120 pt (cuts a lot) | **1,717 µs** | 275 µs |
| 200 pt (cuts some) | 1,203 µs | 283 µs |
| 320 pt (mostly fits) | 218 µs | 233 µs |

## The fix

**A prefix is never narrower than a shorter prefix**, so "the longest prefix that fits" is
monotone and a binary search finds it in log(n) measurements. Same answers, character for
character — the probe that produced the table above compared the two on every title and room and
printed nothing.

The third row is the honest one: where a title already fits, the early return answers and
bisecting is worth nothing. The cost was only ever in the titles that cut, and those are the ones
a narrow column is full of.

**The application had a second copy of this loop.** `health-record-frontend-ziman`'s
`ui/parts.elided` was written before `lib/ui` had one and still walked after the library learned
to bisect, so the library fix did not reach the application that asked for it until the copy was
made to delegate. A second implementation of a library function is a second thing to fix, and this
is what that costs.

The window's build phase went **12 ms to 2**.

## Watched fail

`tests/stdlib/widget_test.zm` gained two tests, and the break watched was the realistic one — the
predicate written `<` instead of `<=`:

- **`elided_cuts_at_the_longest_prefix_that_fits`** pins exact answers at the boundaries against a
  ten-points-a-character fake: a room of exactly 90 holds eight characters and the mark. Reddens
  on the strict predicate (it answers seven).
- **`elided_fits_and_one_more_character_would_not`** sweeps every room from one point to past the
  whole string, against a face whose letters are 2, 10 and 20 points wide, and checks the
  *definition* rather than a second implementation: what comes back fits, and one more character
  would not. Reddens at `30.0 is not greater than 30.0`.

Both reddened; `147 passed, 2 failed`.

**And the first run of that watched fail was a lie**, which is worth recording: it reported
`149 passed, 0 failed` with the break in place, because `lib/ui/widget.zm` is bundled into the
binary and nothing had been rebuilt. Every run before that `make` had been testing the old
library. See the note in [F345](f345.md) and `tools/hooks/pre-push`'s own reasoning about gates
that do not run.

## What the sweep found that was not being looked for

**The bare ellipsis is exempt from fitting.** At a room of one point the mark itself is ten wide
and still comes back, because a label narrower than its own ellipsis has nothing honest to show
and an empty box says less than a mark does. That was pre-existing and undocumented; the test now
says so, and it only came up because the sweep asked about every room rather than a plausible one.
