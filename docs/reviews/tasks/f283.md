# F283 — a glyph the face lacks is `.notdef`, not a crash

Found on 2026-11-12 while using F282: `curly gui` opened on the tree's default marks and **died on
its first frame** with `font.glyphs_of: the face cannot draw U+25BE`. The marks being `Style`
fields made the application's fix two lines, which hid how bad the underlying rule was. It is not
about triangles.

- [x] **F283** **`glyphs_of` and `advance` substitute `.notdef` instead of refusing.** (S;
  `lib/graphics/font.zm`)

  **The text a program draws is not all its own.** Every argument for refusing assumed it was: a
  caller choosing a face for a heading it wrote wants to know its face is wrong. But a REST client
  draws what a server sent, an editor draws what a user typed, and a log viewer draws a file. Under
  the old rule each of those was a way to kill a window, from outside the program.

  **Reproduced rather than argued**, because "could crash" and "does crash" are different claims.
  A scratch server answering `{"ok": "☺"}`, sent from `curly gui`:

  ```
  Error: font.glyphs_of: the face cannot draw U+263A
  ```

  and the window was gone. One character in a response body.

  So both sites take glyph 0 -- which TrueType requires to exist and to be `.notdef`, the box a
  text stack draws for exactly this. **`advance` has to make the same substitution as `glyphs_of`
  or a string measures as one width and draws as another**, which is a caret in the wrong place
  rather than a crash, and so harder to find.

  **The diagnostic is not lost; it moves to where it was always better placed.** `font.covers`
  already answers *which* code point a face cannot draw, and the old error's own last words were
  "check `covers` first". A caller that would rather refuse than draw a row of boxes -- an export,
  say -- asks. A caller drawing a window does not have that option and should not be made to.

  `tests/lang/graphics_text.zm` pinned the refusal and now pins the substitution, the diagnostic
  and the width: `glyphs_of(face, "ok 中")` answers `82 78 3 0`, `covers` answers `U+4E2D`, and
  `advance` of the missing character is greater than zero. Re-run in the window afterwards, the
  same `☺` response draws and the window lives.

  **A note on what `.notdef` looks like.** In Caladea it has no outline, so a missing character
  draws as blank rather than as a box. That is the font's own answer and not something to invent
  here -- but it is why `curly gui` keeps `">"`/`"v"` for its tree marks rather than going back to
  the triangles: drawn as a blank `.notdef`, every folder would look identical and nothing would
  say which was open.
