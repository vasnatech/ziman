# F335 — the first ported screen, and the badge nobody could see

Done 2026-11-20. `lib/ui/controls.zm` and one test here; the screen itself lives in
`health-record/health-record-frontend-ziman`, which is a new application and not part of this
repository.

This is the first screen of the health-record port — §6 step 4 of
[the port plan](../../design/health-record-port.md) — and the first thing it did was find a defect
in a control shipped three days ago.

## The defect

**A quiet badge was invisible.**

`badge_inside` fills the capsule with `paint.flat_of(style.states.rest.face)`. That is a *control's*
resting face, and a badge is drawn straight onto the page. In the modern look the two are:

    rest.face = 0.972 0.977 0.987
    window    = 0.972 0.977 0.987   (to three places)

a contrast of **1.0005:1**. So a quiet badge was a word with nothing around it — which is a label,
and the capsule is the whole of what makes a reader see "badge" rather than "part of the sentence".
On the screen that found it, a row headed `Unable to assess  House dust mite` read as one phrase.

**This is F323's defect over again.** The card was invisible for the same reason — a surface built
from a control colour on a page the plain look leaves nearly identical — and it was fixed the same
way: `style.grid`, the hairline a table already draws with, rather than a second opinion about what
a line is. The loud badge was always fine, because the accent is the one colour that stands out by
construction.

**No test could have had it.** The two badge tests that existed asked what a reader is told
(`"button, Medications, 3"`) and how many nodes a reader visits. Both are the right questions and
neither is about whether the thing can be seen. The new one asks for a contrast ratio — of the fill
**or** the edge, because either would be a fix and the absence of both is the defect — and it
reddens at 1.0005 against a bound of 1.2 with the border removed.

## Why the gallery did not find it first

The gallery has a badge demo and it has been looked at. The badge in it sits beside a button, where
the eye reads the capsule's *absence* as "this badge is the quiet kind" rather than as "this badge
is missing". It took a screen where **quiet badges are the common case and loud ones the exception**
— a status word on every record — for the absence to read as a mistake.

That is worth keeping: a gallery proves a control draws, and an application proves it draws *in the
company it will keep*.

## What the screen found that is not fixed here

Five more things, recorded in the application's own README rather than acted on, because one screen
is not evidence enough to change a toolkit:

| | |
|---|---|
| the two cards | the port's gap list counted `CardShell` (22 files, a titled box — `controls.Card`) and `Card` (7 files, a *row* with trailing actions) as one thing, at "62 files". They are different shapes and this screen needed the second. |
| no scrollable container | everything that scrolls in `lib/ui` is a control that draws its own rows. A column of arbitrary widgets uses `widget.named_scroll` directly — **and then the wheel does not reach it**, because `controls.target` routes a wheel to the nearest *tab stop* and a viewport is not one. |
| the loop, a third time | fonts, density, look, window, poll, lay out, paint, publish, diff, sleep: the same ~200 lines as the gallery and as `curly gui`. `lib/ui` has no "run an application" door. |
| one ink | `Style` has `ink` and `states.disabled.ink`; the target has three text weights and the middle one has no token. |
| `Badge.loud` is a boolean | the target's pill has three colours. "Low" and "unable to assess" are drawn alike here where the target tells them apart. |

The second and third are the two that look like real library gaps rather than preferences. Both
should wait for a second screen to say the same thing.
