# F321 — a table cell holds a value, not a string

Opened 2026-11-19. Asked for as "table control should support values other than string. check
swing jtable tablemodel".

**What `JTable` actually does**, since that was the reference: `TableModel.getColumnClass` returns
a `Class`, and `JTable` looks a renderer up by it in `defaultRenderersByColumnClass`. `Boolean`
draws as a check box, `Number` right-aligns through a `NumberFormat`, `Date` goes through a
`DateFormat`, `Icon` is centred, and everything else falls back to `toString`. That mapping is the
whole feature, and it is why anybody remembers `getColumnClass` exists.

---

- [x] **F321** **`Value`, and a cell drawn as the kind of thing it holds.** (M;
  `lib/ui/controls.zm`, `lib/ui/a11y.zm`, the demo, tests.)

  **An enum where Swing has `Object` plus a `Class`.** Reflection doing a job a type can do: a
  `ClassCastException` at paint time where this is a compile error, and a closed set so a new kind
  of value is a compile error in the one switch that draws them rather than a cell quietly falling
  back to `toString`. The variants are `JTable`'s own default renderers.

  **Why a table needs it at all**: a column of numbers held as text cannot be formatted for a
  locale, cannot be right-aligned on its digits without the caller padding them, and sorts `10`
  before `9`. Holding the value and writing it late fixes all three. The same table now reads
  `1,234.5` under `en_GB` and `1.234,5` under `de_DE` with nothing passed down — the locale is a
  field on the table, injected rather than read from a global, for `Style`'s reason.

  **A `Flag` draws as a check box**, with the check box control's own square and own mark, so a
  flag in a table and a check box in a form are the same thing to look at. It *reads* as
  `a11y.toggle_word` says, which had to become public: a cell saying "checked" while a check box
  beside it says "on" would be the library disagreeing with itself in two places a user meets
  together.

  **`Blank` is not the empty string.** A missing measurement and a measurement of `""` are
  different facts, and a short row -- which a table built from a query gets sooner or later -- has
  the first.

  **Nothing broke.** `table_of` keeps an overload taking `[[string]]`, so every caller written
  before this -- the gallery, the tests, curly's history table -- compiles untouched, and
  `cell_at` still answers a `string` because that is what its callers want. `value_at` is the
  typed door beside it.

  **`Code` exists because the render of the demo found it.** The atomic years were written as
  `Whole` and came out `1,766`. A year identifies rather than counts, and so do a port, a status
  code and an id -- so `Code` is never grouped and never localised. Swing reaches the same place by
  giving the column its own renderer; this says it on the value, where the fact lives. That was
  four minutes of looking at a picture and it is the second time today that rendering caught what
  a green suite did not.

  **`Exact` and `Big` were asked for and the first of them matters.** `decimal` and `bigint` are
  builtin types here, and a column of money held as `Number` is the oldest arithmetic bug there
  is, printed into a table: `Number` is a float and `0.1 + 0.1 + 0.1` is not `0.3` in one. A
  currency column is `Exact`, which is a `decimal` and keeps every digit it was given.
  `number.format` works on the digits a value writes, so both group in the table's own locale —
  a bigint of thirty digits comes out `123.456.789.012.345.678.901.234.567.890` under `de_DE`.

  **`Option<T>` needed no variant, because `Blank` is already the `None` case.** A `Value` whose
  payloads were `Option`s would give the library two spellings for "nothing here" — `Blank` and
  `Number(None)` — and two spellings of one fact is what this module keeps designing against.
  `value_or_blank` is the convenience, overloaded for the types a nullable column usually holds,
  so a caller writes `value_or_blank(row.price)` rather than a switch per cell.

  **There is deliberately none for `Option<int>`**, and the reason is the same one `Code` exists
  for: an `int` does not say whether it is a quantity or an identifier, `Whole` groups and `Code`
  does not, and only the caller knows which was meant. An overload there would have to guess, and
  the guess would be wrong on every year, port and status code.
