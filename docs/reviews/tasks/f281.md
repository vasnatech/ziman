# F281 — the masked field

Raised 2026-11-12 by `curly gui` again, the same way F280 was: the window wanted an Authorization
editor, a Basic password and a Bearer token are both secrets, and `lib/ui` had no field that would
keep one. Building the editor on ordinary entries first was considered and rejected -- a window
that shows a token in clear is not worth one commit of parallelism.

- [x] **F281** **A field for a secret: `controls.password_of`.** (S; `lib/ui/controls.zm`,
  `widget.Role.Password`, 7 unit tests and one bus-level check)

  **A flag on `Entry`, not a second control.** Everything about a password field *is* a text field
  -- the caret, the selection, the undo, the click that places a caret -- and exactly three things
  differ: what is drawn, what role it declares, and that it will not hand its contents to the
  clipboard. `rows` set the precedent; this follows it.

  **`shown_text` is the one string the field is measured against, drawn as, and published as**, and
  that is the whole design. A mask is one bullet per character, so every index into the text is the
  same index into the mask -- but only if nothing measures the other one. `caret_at_x` therefore
  takes `shown_text(e)`, like the widget, for the reason F280's `tab_width` is a single number: a
  layout computed twice is a layout that can disagree with itself. **The test for it needs metrics
  where a bullet is *wider* than the characters it hides**; under the suite's uniform-width metrics
  the mutation is invisible, which is the kind of fixture that looks like a gate and is not.

  **The secret never enters the accessibility tree at all.** The `Focusable`'s `value` carries the
  mask, rather than carrying the text and being filtered somewhere downstream -- a reader, a remote
  bridge and a test dump all read that one string and there is no second place to remember. The
  gate is the real bus, not a unit test: `tests/integration/a11y/tree.zm` publishes a password and
  `tests/run_a11y_test.sh` asserts both that `password text: "Password" = "•••••••" (7 chars)` is
  there **and that `hunter2` appears nowhere in the dump**. That second line is the only check on
  that page that asserts an absence, and it is the one that matters: a field that drew bullets and
  published its contents would pass every other check and read the password out loud.

  **Copy is refused; cut is not.** A control whose purpose is that its text is not shown cannot be
  the thing that puts it on a clipboard every other program can read. What that broke on the first
  pass is worth keeping: `cut_from` decided "nothing to do" by testing the *copied string*, which
  is `""` for a masked field by design -- so Ctrl-X became a key that did nothing in the one field
  where deleting a selection matters most. It asks `edit.has_selection` now.

  **A masked field is one line whatever `rows` says.** `multi_line_widget` draws the text, so
  leaving `rows` able to pick the path would leave a way to build a field that masks in one place
  and not the other.

  `widget.Role.Password` → `ATK_ROLE_PASSWORD_TEXT`. Two switches over `Role` have no default arm,
  by design, so the compiler named both.

  Four mutations, and what each proved: measuring the text instead of the mask in `entry_input` is
  caught **only** by the wide-bullet test; publishing `e.editor.text` is caught by two unit tests
  and by both bus checks; restoring the `text == ""` no-op is caught by the cut test. Each test
  that asserts a refusal also asserts the same gesture *works* on an ordinary field, or it would
  pass against a field that simply never copies anything.
