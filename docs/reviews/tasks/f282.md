# F282 — the tree

Raised 2026-11-12 by `curly gui` for the third time in a day, and this one is not a missing field
but a missing shape: the sidebar is a flat list of `collection/path` strings where the storage has
folders, so a request in `Auth/OAuth/refresh` is a long label rather than something three levels
down. `widget.State.expanded` has existed since F275 and nothing declared `Tree` or `TreeItem` --
the same gap `Tab` and `TabList` were in before F280, found the same way.

- [x] **F282** **A tree: `controls.Tree`.** (M; `lib/ui/controls.zm`, 16 unit tests and 5
  bus-level checks)

  **Flat with a depth, not nested.** A nested structure has to be walked to draw, walked to
  hit-test and walked again to move the selection, and all three walks are the same projection --
  the rows in order, minus what sits under a closed branch. Doing it once, as a list, is what
  leaves the rest of this control as the list's code with an indent. `visible_rows` is that
  projection and is one pass, not a per-row "is any ancestor closed" test, which would be the same
  walk done n times.

  **`expandable` is declared, not derived from the next row's depth.** A branch with nothing in it
  yet is still a branch: a tree that inferred it would draw an empty folder as a leaf and leave a
  user unable to tell an empty folder from a missing one. The fixture has an empty branch for
  exactly this, and the test asserts it still opens and closes while hiding nothing.

  **`selected` is an index into `rows`, never into the visible ones.** An index into a projection
  moves to a different thing the moment a branch closes above it.

  **The arrow contract is the difference between a tree and an indented list**, so it is here in
  full: Right opens a closed branch and *steps into* an open one, so Right-Right walks downwards
  rather than stopping on the first folder; Left closes an open branch and from a leaf climbs to
  the parent, which is the move that makes a deep tree navigable -- without it the only way out of
  a folder is Up past every sibling. Toggling never moves the selection, or Right-then-Left is not
  a round trip and a user loses their place every time they look inside a folder.

  **One number for the indent, shared by the layout and the hit test**, F280's `tab_width` rule a
  second time: a press in the one indent-wide column at a row's own depth toggles it and a press
  anywhere else selects. A leaf has no mark, so that column is part of its label and a press there
  must select rather than quietly do nothing -- a third of every leaf row would otherwise be dead.

  **The marks live in `Style`.** This layer is handed whatever font bytes an application found and
  cannot know what is in them; a face without triangles would draw two empty boxes and leave every
  folder looking identical. `"▸"`/`"▾"` by default, and an application that knows its font
  can put `">"`/`"v"` there.

  `widget.Role.Tree`/`TreeItem` → `ATK_ROLE_TREE`/`ATK_ROLE_TREE_ITEM`. The state was already
  there: `State.expanded` is an `Option<bool>` and `atspi` already published EXPANDABLE for
  `Some(_)` and EXPANDED for `Some(true)`. **A leaf declares `None`**, because `Some(false)`
  publishes EXPANDABLE and a reader would offer to open something that cannot be opened.

  Two things about the gate rather than the control. **`atspi_dump` did not print `expandable`**,
  so a collapsed branch and a leaf dumped identically -- the fourth time on this project a tool
  has made a correct publication look absent, and this time it was found before it cost anything.
  And the leaf's absence needed its own check: `check 'tree item: "login"'` is a prefix match and
  matches a leaf that published both states, so the absence is asserted separately. Its first
  version printed an empty failure message, because the grep inside it was quoted wrong -- fixed
  after watching the mutation fail, which is the only way that was ever going to be noticed.

  **The parts nest, though the rows are flat and the layout is a plain column** -- and the first
  version did not, which is the finding worth keeping. A reader asks a node for its children, so a
  branch whose rows were siblings of it says that seven things exist and nothing about which is
  inside which: an indented list again, seen from the one side that cannot see the indent. Every
  unit test passed, the roles were right and the states were right; **it was visible only in the
  AT-SPI dump of the real application**, which printed seven tree items in a flat row. Nesting
  costs nothing in layout, because a part adds no box of its own and the rows keep their absolute
  indent, so a column of columns of fixed-height rows stacks exactly as one column does -- which
  is what keeps `y / row_height` true. Two unit tests and one bus check now assert the hierarchy;
  flattening the parts again fails one of each.

  **A default a font cannot draw is a crash, not a fallback.** `curly gui` opened on the triangles
  and died on its first frame with "the face cannot draw U+25BE", because the face it vendors is a
  text font. That `Style` carries the two marks is why the application's fix was two lines -- but
  the deeper fact is that `font.glyphs_of` **raises** on a glyph the face lacks, so any text a user
  can type is a way to kill a window. That is not this task's to fix and is worth its own.

  Six mutations: hiding only direct children is caught by three tests; moving the mark column one
  indent right is caught by eight; a leaf claiming `expandable` by one unit test and one bus check;
  removing Left's climb to the parent by one; moving the selection on toggle by one; and flattening the accessibility parts by one unit test and one bus check.
