# F340 — a list row that is an icon *and* its words

Done 2026-11-20. `lib/ui/controls.zm`, two tests.

`Value` could say `Mark(widget.Icon)` or `Text(string)`. It could not say both, and a `List` row
holds one `Value` — so the commonest row on any desktop could not be written: **a file beside its
kind, a place beside its sign, a screen beside its symbol in a sidebar.**

Found by the health-record port, whose sidebar is the target's `<span className="w-7">{icon}</span>`
followed by a label. The alternatives were both bad: lay out `controls.Button`s by hand, which is a
tab strip with none of a listbox's selection, keys or `Role.ListItem`; or draw the words alone,
which is what it did and what looked least like the thing it copies.

## What changed

`Value.Marked(MarkedValue)`, where `MarkedValue` is `{ mark, words }`.

**A struct and not two payloads on the variant**, because a pattern here binds one value:
`Marked(mark, words)` is a syntax error, and every multi-field variant in this library is a struct
for the same reason. Worth writing down — it is not obvious from the declaration, which the parser
accepts.

**The words are the value.** `value_text` answers the string, so sorting, filtering and what a
reader is told are all unchanged by decorating a row. An icon a reader would need is one that
should have been words — so the icon is a mark on the value, never the value.

**One arm per variant, which the compiler demands.** Adding the variant named every exhaustive
switch over `Value`, which is how a new kind of value is a compile error in the one place that
draws it rather than a cell falling back to its text. The new `row_content` is written out the same
way for the same reason, rather than with the default arm this project does not have.

**And the row's ink reaches the icon.** A selected row whose look paints the band in the accent
needs `on_accent` for both; an icon left in the list's ink vanishes into the band exactly as the
text would.

## A table gets it too

`cell_content` is the same switch, so an icon-and-words cell is a table cell as well as a list row —
which is the point of `Value` being shared. The shape is built once in `marked_row`, so a sidebar
and a column of files are the same thing to look at.

## Watched fail

Pointing `Marked` at the plain label path reddens
`a_marked_row_draws_its_icon_and_its_words`, at 5 ops against 5 — the icon's ink gone and nothing
else changed. Counted through the groups, because an icon is painted inside one; counting only the
top level gave 0 for both lists and would have passed whatever the row drew.

## Not done

**`List` still has no icon of its own**, only rows that carry one. A list whose every row takes the
same icon has to say so per row, which is fine for two rows and would not be for two hundred. No
caller has wanted it yet.
