# Ziman — Design

Ziman ("language" in Kurdish) is a small, statically-typed language designed
to be cheap for an LLM to generate correctly and cheap for a human to read
without running it. It is not modeled on C — C is only this project's
*implementation* host (the interpreter is written in C; see README for why).
Ziman's own syntax and semantics are designed from scratch: it is not
designed to be tree-native/structural either — it's a normal parsed text
language, but every syntax and semantics decision is chosen to remove a
class of error that shows up often in LLM-generated and human-written code
alike, borrowing individual ideas (explicit mutability, no coercion) from
several languages rather than inheriting any one of them wholesale.

## How to read this journal

A dated decision log, not a specification: [docs/syntax/](../../syntax/README.md) says what the
language *is*, and this says why each decision was made and what was tried. Two things follow from
that.

**It is a folder, and the Index below is the way in.** The entries live in numbered parts, plus
`principles.md` and `v0-decisions.md`; the index lists every entry with the part it is in and is
regenerated by `tools/gen_design_index.py`, so it cannot fall out of date. This was one
10,449-line, 1.2 MB file until 2026-10-30 -- more than fits in a context window, so neither a
person nor a model could read it in a pass, and two documentation errors came of reading around it
instead of through it.

**The parts are numbered rather than dated, because these entries are not in date order.** The log
opens in mid-October, drops back to early October and then to September. A part named for the date
it starts at would claim an ordering the entries do not have, so each part is numbered in the
document's own order and its title states the range it actually spans. A new entry goes at the end
of the last part.

**An entry written before 2026-10-30 names the paths of its own date**, which is the same rule as
everything else here: `DESIGN.md` is this folder, `SYNTAX.md` is `docs/syntax/`, `ROADMAP.md` is
`docs/roadmap/` and `docs/reviews/tasks.md` is `docs/reviews/tasks/`. Those references were left as
written rather than rewritten, because an entry is a record of what was done and said on a day, and
editing it to agree with today is exactly the drift the dating is there to prevent.

**An entry is true of its date.** A later entry may be the current answer, and the earlier one then
records how it started -- the formatter has two entries for exactly that reason. Where that happens,
the earlier one carries a bold **Extended by** or **Superseded in part** line naming the later one,
with the date it was added, and the later one points back. If you are looking for the current state
of something, read to the end of what the index lists for it rather than stopping at the first hit.

**A "Not yet" list is the most perishable thing here**, which is why `tools/check_not_yet.py` scans
this file: a "Not yet" naming an identifier in backticks is checked against what is actually `pub`,
and `make docs-check` fails when one has landed. It cannot check a prose item -- "Not yet: HTTP/2,
multipart" names nothing to look up -- so those are still only as current as the last person to read
them against the code.
